# Antigravity context and delegation setup

The portable starting point is the pasted prompt plus explicit file reads. Keep `GEMINI.md` concise and store detailed context in the linked docs/coverage tracker. Add a reference pointer to the **app workspace** while preserving its existing instructions; rules in a sibling reference checkout do not automatically govern the app.

Google's current rules documentation supports `GEMINI.md`/`AGENTS.md` and workspace rule files. This kit includes small modern and legacy pointer files; use the form recognized by the installed surface. Do not create or overwrite global user instructions. Read [Google's rules documentation](https://antigravity.google/docs/rules/).

Use the active environment's native subagent tools and `TEAM-PLAN.md` role descriptions. Give every worker full paths, owned files and reference IDs because subagents may start without parent conversation history. The capability and model selection belong to the installed environment; this kit does not hardcode tool schemas or model names. If delegation is absent, run the roles sequentially and disclose that limitation. See [Google's subagent documentation](https://antigravity.google/docs/subagents/).

No legacy slash workflow is required. The official IDE workflow page announces a workflow transition, so this handoff relies on the durable prompt/rules/tracker instead. See [Google's workflow notice](https://antigravity.google/docs/ide/workflows/). Documentation checked29October2026; recheck if installed behavior differs.

To keep context throughout one long session: update the task tracker after each phase, retain exact source/commit/evidence paths, mark blockers per screen, and reread the tracker after compaction. “Remember” means persisted, reviewable project context—not an assumption that Gemini retains an earlier chat.
